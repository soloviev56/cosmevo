## 3. Как писать статью

Образец стиля — опубликованные статьи (первая —
`methods/scales/units-scales.qmd`). Перед первой статьёй порции прочитай
целиком хотя бы одну из них.

Читатель — магистрант-теоретик: стандартный курс теоретической физики
(включая ОТО, статфизику, кинетику и основы КТП) считается известным, его
не пересказывают, а используют. Выводы — полные, с указанием
приближений; оценки — с численными множителями, а не только «по порядку».

Структура: мотивация → определения (`::: {#def-...}`) → вывод и
вычисления, проверенные кодом → физика и наблюдательный статус →
«Итоги» → 5 упражнений с ответами в свёрнутом блоке `callout-tip` →
«Литература» (полные ссылки). Заголовок файла: `title`, `topic`, `order`,
`description` (без `level`, `status` и `requires` — они в карте).
Ссылки на другие статьи — относительные пути `.qmd` от корня
(`/methods/...`, `/evolution/...`). Ссылайся только на темы, которые есть
в `topics.yml`, и называй их точно так, как там.

Обязательные правила.

- **Статус утверждений.** Каждое содержательное утверждение, статус
  которого не очевиден, помечается `[У]{.status}`, `[Г]{.status}` или
  `[С]{.status}` по `conventions.qmd`. Гипотеза никогда не излагается как
  установленный факт, спекуляция — как гипотеза. Нет телеологии: «материя
  стремится», «эволюция ведёт к» — только если это цитата, которую
  разбирают.
- **Источники.** Ссылайся только на работы, в существовании и выходных
  данных которых уверен. Если не уверен в томе, странице или годе —
  проверь (поиск в интернете, arXiv), а если проверить нельзя — укажи
  только авторов, год и arXiv-номер, в котором уверен, и запиши в журнал
  «проверить ссылку». Выдуманная ссылка — самая тяжёлая ошибка в этом
  пособии.
- **Свежие данные** (DESI, JWST, Planck, ограничения на распад протона и
  т. п.) датируются: «по данным на 2025 г.».
- **Конвенции.** Все единицы, знаки и обозначения — строго по
  `conventions.qmd`. Константы — из `astropy.constants`, космология —
  `astropy.cosmology.Planck18`, перевод единиц — `cosmevo.units`. Если
  статье нужна новая конвенция, сначала добавь её в `conventions.qmd` и
  тест в `tests/test_conventions.py`, и обязательно упомяни это в отчёте
  отдельным пунктом.
- **Каждая формула проверена кодом** (SymPy — тождества и выводы, NumPy/
  SciPy — численные решения). Если `simplify` не справляется — `rewrite`,
  численная подстановка.
- **Каждый ответ упражнения и каждое число в тексте пересчитай кодом**
  до коммита. Удобно — скрытой ячейкой с `assert` в конце статьи
  (`#| echo: false`, `#| output: false`), как в образце. Текст должен
  совпадать с реальным выводом ячеек.
- **Числа SymPy в f-строках** оборачивай в `int()`/`float()`.
- **Каждый рисунок посмотри** (Read PNG из `_site/.../figure-html/`):
  наложения подписей, пустые заливки, вводящие в заблуждение масштабы.
  Подпись рисунка должна соответствовать данным.
- Код читаем: короткие функции, комментарии по делу, как в соседних
  статьях. Общие инструменты, нужные нескольким статьям, — в пакет
  `src/cosmevo` с тестами в `tests/`.

Проверка перед коммитом каждой статьи:

```
~/miniconda3/bin/conda run --no-capture-output -n cosmevo python -m pytest -q
~/miniconda3/bin/conda run --no-capture-output -n cosmevo quarto render
```

Обе команды без ошибок; выводы ячеек статьи просмотрены (извлеки текст
`cell-output` из HTML в `_site`), блок «Уровень и связи» на месте.

Коммит — по одной статье, сообщение по образцу `git log`
(«Статья «…»» + краткое содержание), подпись автора берётся из
локального git-конфига, в конце строка
`Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
После каждого коммита — `git push origin main`, чтобы готовые статьи
публиковались, даже если работа прервётся.
